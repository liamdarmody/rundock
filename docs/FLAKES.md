# Flaky tests

**The rule: a test that flakes twice is fixed or quarantined.** A flake is a
test that failed and then passed on the same code. The first time, add a row
here. The second time, fix it, or quarantine it (skip it with a pointer to its
row) until it is fixed. A third re-run is not one of the options.

One row per test: the test, the dates it flaked, the cause as far as it is
known, and its status. Status is one of `retry once`, `open`, `fixed` or
`quarantined`. `retry once` is a single retry for that test alone, configured
in a `test.describe` that holds only it; the browser suite has no global retry,
because a retry hides a timing regression as readily as a slow runner.
`test/unit/flake-register.test.js` holds every retry in the suite to this page.
A pass on a retry is a strike too, and a passing run would hide it, so
`test/e2e/flake-reporter.js` reports each one: a warning annotation in CI, a
plain `[flake]` line locally. Add its date to the test's row.

Before fixing one, read [TEST-TIMING.md](TEST-TIMING.md): most flakes here are
timing assertions, and it says how to tell a wait that is needed from one that
hides a defect.

## CI and release gate steps

A step that fails for a reason outside the code is held to the same two-strike rule.

- **Release gate "personas (stub)"** (once, in a gate run on a loaded machine; it passed alone, 16 of 16). The journeys slept a fixed 1.5 seconds after signing in before sending on the page's socket, and started conversations with the team the journey had just created half a second after asking, while the roster naming that team could still be on its way to the page; the client then opens a conversation with the first agent it knows instead, and the message goes to the wrong agent. Fixed 2026-10-24: the journeys wait for the socket to be open and the workspace named, and for the roster to hold the agent, and check that the conversation that opened is with it (`scripts/smoke/page-ready.mjs`). Found by reading the code, not from the failing output. It failed again on 2026-11-01 at "NEW-USER first delegation works in the fresh workspace", with "the page's roster never held chief-of-staff within 30s". That was the fix itself, not the machine: the roster gives an agent with `order: 0` the id `default`, whatever its file is called, so the wait for `chief-of-staff` could never end, and no gate had run the journey since the wait was added. Fixed 2026-11-02: the journey asks for `default`, and `test/unit/page-ready.test.js` holds the journey's own file to the roster's rule. If the step fails again, note here which check failed.
- **Coverage floors** (2026-11-05, three times: twice on #400's final head, which passed on the third attempt, and once on its earlier head, each with `lib/scheduler.js` unchanged). The cut that keeps a routine's stderr capture to its last 4 KB reads the size and the tail again when the file grew while it was being cut, and the only tests that reached those lines used a real child, so they ran only when one of its writes landed between two looks. Fixed 2026-11-06: the cut reads the size and the tail through dependencies the tests wire, and the ending hands what it read back to a third, so `test/unit/scheduler-capture-cut.test.js` makes the file grow, or a look or a read fail, on the look it chooses, on every run, and compares the bytes kept with the last 4 KB written. Three coverage runs on commit 31f3c000 covered the same 2598 of the file's 2602 lines; its header records them compared line by line. If the job fails again on `lib/scheduler.js`, note here which lines.
- **E2E "Install Chromium"** (2026-10-22, twice). A slow package mirror stalled the first attempt; `timeout` ended the installer but not the `apt-get` it had started as root, which kept the dpkg lock, so the second and third attempts failed on the lock at once. Fixed 2026-10-22: each retry waits for any package manager still running.
- **Test (Node 22) job stalled until cancelled** (2026-11-09, 2026-11-10). On the first attempt of CI run 42799546862 the job reported nothing after `test/unit/codex-startup-files.test.js` finished: the next file, `test/unit/codex-what-runs-guard.test.js`, printed its output but no results, and the job was cancelled exactly 25 minutes after it started. The second and third attempts ran the whole suite in under nine minutes. The Node 22 job of CI run 42701962977, on another pull request, was cancelled exactly 25 minutes after it started on 2026-11-09 while Node 24 passed in eight; its log has expired, so whether it stalled in the same place is not known. Cause not known. If it stalls again, note here which file it stalled after.
