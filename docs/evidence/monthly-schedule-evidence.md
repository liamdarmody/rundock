# Monthly schedules: the mutation rows, and their costs

This change lets a routine run once a month and moves every reader of a schedule onto one period helper. That rewrote lines that mutation rows quote, and added guards that need rows of their own. This file lists every row the change rewrote or added, in each harness it touched, with a run of each, and says what the change does to the mutation cost table.

## How each row was run

Each row was run with `node test/tools/<harness> --rows A:B` on the head that carries this file. The commit that adds this file changes nothing else, so the source and tests are those of the commit before it. The harness applies one row at a time and restores the file between rows, so a slice of adjacent rows reports each row exactly as a run of that row alone would. The three rows added last were run alone.

A row whose text matches nowhere is reported as not found, and one whose text matches more than once is refused as ambiguous. Every row below was applied, so each matched its text exactly once. Beyond these, every row in all three harnesses was checked to match its text exactly once on this head, by splitting its source file on the row's search text, so no row still quotes a line this change moved.

The last three guard the hold. Before they were added, a rule that waived a monthly slot for any recorded hold, whether the slot came before the hold or after it, passed every test, and so did a slot store that dropped the hold on reading it back. A tick that never writes the hold was already caught by the earlier hold tests, and its row makes that a guard rather than a coincidence.

## The cost table

`test/tools/mutation-costs.json` prices rows by label for the shard planner. A row with no price of its own is planned at its harness's rate, which for the routines harness is 1.33 seconds a row.

- **Four rows that were already in the harness have no price, as on main:** "the slot the last run served is named", "the slot a run served is the one on the day it started", "the anchor is the period now falls in, not the last one a tick recorded", and "a row can name a next run before any tick has seen the routine". This change rewrote the line each one quotes, not the suite it runs or the work it does, so the harness rate still fits them as it did on main. Planning this change's scoped set with `node scripts/mutation-scope.js --plan` gives the same ten shards with the four prices and without them, the longest planned at 628 seconds with them and 629 without. The planner does not need them, so they were dropped.
- **The five rows the change added first keep their measured prices,** from 0.3 to 1.4 seconds.
- **The three hold rows have no price.** They run `test/integration/scheduler-monthly.test.js`, the suite the two priced monthly rows run at 1.2 and 1.4 seconds, within 0.2 seconds of the harness rate they are planned at, so a price would not move the plan.
